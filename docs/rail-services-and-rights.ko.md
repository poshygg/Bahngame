# 실제 철도 서비스·차량 표현과 게임 확장 검토

구현 현황(0.4): OSM 출처가 있는 실제 서비스 기반 솔로 챕터와 개인 경로는 구현했다. 아래 PVP·고스트 경쟁 규칙은 제안이며, 데이터 범위와 수집 방법은 [독일 노선 데이터 문서](germany-rail-catalog.md)를 기준으로 한다.

확인일: **2026-09-13**. 독일·EU 법령, Deutsche Bahn(DB), 운영사·교통연합의 공식 공개 자료를 기준으로 작성했다. 아래 법률 부분은 구현 범위를 정하기 위한 위험 검토이며, 특정 차량·이미지의 사용을 승인하거나 침해 여부를 확정하는 법률 의견은 아니다. 게임 규칙은 별도로 표시한 제품 제안이다.

## 권장하는 제작 범위

**실제 역명과 출처를 확인한 노선 정보를 사용하고, 지도 위에서는 직접 디자인한 무브랜드 열차를 움직이는 방식으로 개발을 진행할 수 있다.** DB 로고·ICE 로고·특정 편성의 외형을 그대로 재현하거나 공식 사진을 게임 에셋으로 쓰려면 별도의 권리 검토가 필요하다. 로고만 지웠다고 모든 권리가 해결되지는 않는다. 이는 아래 공식 자료를 토대로 한 제작 방향이지, 개별 에셋에 대한 법적 보장은 아니다.

| 사용하려는 것 | 구분해야 하는 권리 | 이 프로젝트에서의 처리 제안 |
| --- | --- | --- |
| Berlin Hbf 같은 역명, 정차 순서·운영사·서비스 종류라는 사실 | 사실 자체와 창작된 설명·노선도·데이터베이스는 다르다. 서비스명을 설명하는 사용과 게임의 자체 브랜드로 사용하는 것도 다르다. | 역명은 입력 대상으로, 서비스명은 출처가 있는 사실 설명으로 표시한다. 설명문과 노선 그래픽은 직접 작성하고 공식 제휴를 암시하지 않는다. |
| 시간표 전체, 정차 데이터 대량 수집, API 응답 | 데이터베이스 권리, API·데이터셋별 이용 조건 | 승인된 데이터셋·API를 사용하고 출처·라이선스·갱신일을 저장한다. 웹에서 보인다는 이유로 전체 시간표를 복제하지 않는다. |
| DB/ICE 로고와 이름을 차량·상점·앱 아이콘에 크게 사용 | 상표, 로고의 저작권·디자인권 가능성 | 현재 단계에서는 에셋에 넣지 않는다. 사실 설명에 필요한 텍스트 사용도 표시 방식과 공식성 오인을 검토한다. |
| 실제 ICE의 차두부·창문 배열·도색을 충실히 재현한 2D/3D 열차 | 등록디자인, 창작성이 있는 응용미술의 저작권, 출처 표시로 기능하는 외형·색채의 상표 문제 가능성 | 모델별 권리자·권리 범위·존속 여부를 확인한 뒤 결정한다. 똑같이 만든 후 로고만 삭제하는 방식으로 안전하다고 판단하지 않는다. |
| DB 보도 사진, 검색 이미지, 판매·무료 배포 3D 모델 | 사진가·모델 제작자의 권리와 묘사된 차량의 권리는 별개 | 각 에셋의 게임 내 배포·수정·상업 이용 범위를 확인한다. 구매, 출처 표기, 무료 다운로드만으로 모든 권리가 확보됐다고 보지 않는다. |
| 직접 그린 독창적인 일반 열차 | 특정 차량의 보호되는 표현을 따라 했는지에 따라 판단이 달라짐 | 자체 색상·차두부·창문 비례·장식을 설계하고 제작 과정을 남긴다. 이 방법은 위험을 줄이지만 자동 면책은 아니다. |

독일 저작권법은 개인의 지적 창작물을 보호하고 응용미술·사진·도면 등을 예시한다. 일반 사진에는 별도의 사진 보호 규정도 있다. 상표법은 상업적 사용에서 혼동 등의 요건에 따른 보호와, 정직한 거래 관행에 부합하는 식별·참조 사용의 제한 규정을 함께 둔다. 따라서 사실 정보를 쓴다는 이유만으로 로고나 창작 이미지를 같이 가져올 수 있는 것은 아니다. [UrhG §2](https://www.gesetze-im-internet.de/urhg/__2.html), [UrhG §72](https://www.gesetze-im-internet.de/urhg/__72.html), [MarkenG §14](https://www.gesetze-im-internet.de/markeng/__14.html), [MarkenG §23](https://www.gesetze-im-internet.de/markeng/__23.html)

## DB 공식 자료에서 확인되는 허용 범위

**DB Marketingportal에 접근하거나 가입했다고 에셋 사용권을 얻는 것은 아니다.** 이용약관 §5는 별도 합의한 라이선스 또는 법률상 허용 범위가 필요하다고 명시한다. 이 포털은 DB 업무를 위한 자산 제공을 전제로 하므로, 공개 열람 가능한 가이드가 곧 외부 게임 제작용 라이선스는 아니다. [DB Marketingportal 이용약관, 2022년 1월 표기](https://marketingportal.extranet.deutschebahn.com/neues-design/Nutzungsbedingungen-14025352)

**DB Mediathek의 무료 사진도 일반 게임용 무료 에셋이 아니다.** 2024년 12월판 약관 I.2에서 외부 사용은 기본적으로 보도·편집 목적이며, 그 밖의 사용, 특히 상업·마케팅 사용에는 특별 합의가 필요하다. 개인 용도도 허용하지 않는다. 기본 조건에는 1회 사용, 미사용 시 2개월 후 권리 소멸, 계속 보관 제한, 수정 및 재허락 제한도 있다. 약관은 허용된 이용 범위 안에서는 사진에 담긴 DB 소유 저작권·디자인권·상표권도 포함한다고 설명하지만, 그 범위가 게임 사용으로 자동 확장되지는 않는다. [DB Mediathek 이용약관 I.2–I.6](https://mediathek.deutschebahn.com/marsDB/en/instance/ko/GTC.xhtml?oid=2721582)

직접 촬영하더라도 사진 촬영 허가와 이후 게임 내 이용은 구분해야 한다. DB는 자사 시설에서 상업 촬영을 위한 사전 서면 허가 절차를 안내하고, 공개적으로 접근 가능한 구역에서의 사적·비상업적 촬영을 별도로 설명한다. 이는 DB 시설에 관한 안내이지 모든 공공장소 촬영에 DB 허가가 필요하다는 뜻은 아니다. [DB 촬영 허가 FAQ](https://www.deutschebahn.com/de/presse/drehgenehmigung-6868464)

DB가 공식 안내하는 상표·디자인·라이선스 문의 창구는 **markenrecht@deutschebahn.com**이다. 같은 페이지의 제3자 DB 로고 안내는 거래 관계를 소개하는 **레퍼런스 용도**의 서면 라이선스에 관한 것으로, 게임에 사용할 수 있다는 약속은 아니다. 실제 차량을 넣기로 결정하면 다음 내용을 담은 시안으로 문의하는 것이 적합하다. **이번 조사에서 외부 연락은 하지 않았다.** [DB 로고 법적 안내 및 라이선스 연락처](https://marketingportal.extranet.deutschebahn.com/marketingportal/Marke-und-Design/Basiselemente/Logo/Rechtliches)

- 재현할 정확한 차량 형식, 로고·도색·실루엣, 자체 제작인지 공식 모델 제공이 필요한지.
- 지도 위 크기·각도·애니메이션, 게임 화면과 앱스토어·광고용 화면 시안.
- 웹·Windows·Android·iOS, 배포 국가, 서비스 기간.
- 무료·유료 판매·광고·인앱 구매 여부, 수정·최적화·번들 배포 범위.
- 해당 창구가 허락할 수 있는 권리와 제조사·디자이너 등 다른 권리자 확인 필요 여부.
- 출처 표기, 승인 절차, 비용, 계약 종료 후 에셋 교체 조건.

## 차량 외형과 무료 MVP에 관한 주의점

독일 등록디자인은 이용자에게 주는 전체적 인상 등을 기준으로 보호 범위를 판단한다. 개별 ICE 형식의 현재 등록 상태, 도색의 상표 보호, DB와 제조사·설계자 사이의 권리 귀속은 **이번 조사에서 등록부·계약 단위로 확인하지 않았다.** 빨간 줄이나 특정 차두부만으로 무조건 침해라고 할 수 없으며, 반대로 로고가 없다는 이유만으로 사용 가능하다고 확정할 수도 없다. [DesignG §38](https://www.gesetze-im-internet.de/geschmmg_2004/__38.html)

EU 디자인 제도는 2025년부터 비물리적 제품 및 움직임·전환을 포함하는 정의를 명확히 했고, 2026년 7월 후속 변경도 적용됐다. 따라서 게임 화면의 2D·3D 표현이라는 이유만으로 디자인권 검토를 생략하면 안 된다. 다만 실제 권리 범위와 예외가 해당 에셋에 적용되는지는 별도 판단이다. [EUIPO 개정 안내](https://www.euipo.europa.eu/news/it-is-finally-real-changes-to-eu-design-law-start-to-take-effect), [EUIPO 현행 개정 허브](https://www.euipo.europa.eu/en/designs/design-reform-hub), [규칙 (EU) 2024/2822, 개정 제3·19·20조](https://eur-lex.europa.eu/eli/reg/2024/2822/oj/eng)

관련된 실제 판례로 독일 연방대법원의 **2011-04-07, I ZR 56/09, “ICE”**가 있다. 공식 판결 요지는 당시 디자인법상 인용 목적의 재현에 인용자의 설명과 재현된 디자인 사이의 내적 관련성이 필요하다는 것이다. 이는 **실용신안 판결이 아니라 당시 Geschmacksmuster, 즉 디자인 보호에 관한 판결**이다. 단순 장식용 열차 이미지에 ‘교육용 게임’이라는 이름을 붙이면 허용된다는 근거로 쓸 수 없다. 이 오래된 판결을 현재 모든 ICE 형식의 유효한 권리나 게임 내 사용 금지의 증명으로 확대하지 않는다. 공식 PDF의 검색 색인에서 사건번호·일자·판결 요지를 확인했으며 직접 PDF 열람은 서버 접근 오류로 제한됐다. [BGH 공식 판결](https://juris.bundesgerichtshof.de/cgi-bin/rechtsprechung/document.py?Art=pm&Blank=1&Datum=2011-4&Gericht=bgh&file=dokument.pdf&linked=urt&nr=57668)

**무료 배포·비영리 MVP는 포괄적 면제 사유가 아니다.** 독일 디자인법의 사적·비상업적 행위 예외는 두 요건을 함께 요구하며, 공개 배포가 자동으로 사적 이용에 해당하지 않는다. 인용·교육 예외에도 조건이 있다. EU 디자인법 역시 사적·비상업적 행위와 인용·참조·비평 등의 예외를 구분한다. 특정 외형을 충실히 재현해 공개 출시하려면 배포 시장과 완성된 에셋을 기준으로 권리자 또는 독일·EU 지식재산 전문가에게 확인하는 단계가 필요하다. [DesignG §40](https://www.gesetze-im-internet.de/geschmmg_2004/__40.html), [규칙 (EU) 2024/2822의 개정 제20조](https://eur-lex.europa.eu/eli/reg/2024/2822/oj/eng)

## 사실 정보·시간표·지도·에셋은 따로 관리

데이터베이스의 전부 또는 상당 부분을 복제·재이용하거나, 작은 부분이라도 반복·체계적으로 추출하는 행위에는 별도 데이터베이스 권리가 문제될 수 있다. 노선도가 사실을 나타낸다고 해서 PDF의 그래픽 구성이나 대규모 데이터 추출까지 자유로운 것은 아니다. [독일 UrhG §87b, 법령 전체 본문](https://www.gesetze-im-internet.de/urhg/BJNR012730965.html)

실시간 정보를 나중에 붙인다면 공식 **DB Timetables API**는 검토 가능한 출발점이다. 확인 당시 제품 페이지는 데이터셋을 **CC BY 4.0**으로 표시했고, 역별 도착·출발 및 계획·변경 정보를 제공했다. 이것이 모든 DB API·웹사이트 시간표에 같은 라이선스가 있다는 뜻은 아니다. API별 약관·호출 제한을 함께 확인해야 한다. [DB Timetables API](https://developers.deutschebahn.com/db-api-marketplace/apis/product/timetables), [DB API Marketplace 약관](https://developers.deutschebahn.com/db-api-marketplace/apis/nutzungsbedingungen)

CC BY 4.0 이용 시 적절한 출처, 라이선스 링크, 변경 여부를 표시해야 하고 공식 후원을 암시하면 안 된다. 이 라이선스는 특허·상표권을 허락하지 않으므로, DB 데이터의 허용 범위를 DB 로고·차량 모델에 옮겨 적용하면 안 된다. 사진·모델 판매자가 자신이 가진 저작권만 허락하는 경우도 같은 구분이 필요하다. [CC BY 4.0 요약](https://creativecommons.org/licenses/by/4.0/), [법률문 §2(b), §3](https://creativecommons.org/licenses/by/4.0/legalcode.en)

게임 데이터는 `sourceUrl`, `checkedAt`, `license`, `attribution`, `variant`를 보관하고, 차량 에셋에는 추가로 권리자·계약 범위·수정 가능 여부·만료일을 기록하는 구조를 제안한다. **데이터 라이선스와 차량 아트 라이선스를 별도 항목으로 둔다.** 현재 지리 데이터와 지도 출처는 [map-sources.md](map-sources.md)에 정리돼 있다. 현재 역 좌표를 잇는 선은 실제 철도 선형·터널·분기기를 재현한 것이 아니므로, 실제 열차 모양을 넣더라도 정확한 선로를 달린다고 표시하지 않는다.

VBB는 Magdeburg–Brandenburg–Potsdam–Berlin–Frankfurt (Oder) 축과 여러 정차 변형을 안내한다. **모든 RE가 DB 운행은 아니다.** | Potsdam Hbf → Berlin-Wannsee → Berlin-Charlottenburg → Berlin Zoologischer Garten → Berlin Hbf → Berlin Friedrichstraße → Berlin Alexanderplatz → Berlin Ostbahnhof → Berlin Ostkreuz. 도심 관광 입문용으로 선택한 연속 구간. [VBB RE1](https://www.vbb.de/unterwegs-im-vbb/regionalbahnlinien/re1/), [ODEG 노선 안내](https://www.odeg.de/linien-fahrplaene/liniennetz-fahrplaene) |
| 독일 / Berlin–München / ICE Sprinter | DB는 Berlin / Halle / Erfurt – Nürnberg / München 축을 ICE Sprinter 연결로 안내한다. | Berlin → Halle (Saale) → Erfurt → Nürnberg → München을 주요 도시 챕터로 사용한다. **특정 열차편의 모든 정차역 목록은 아니다.** 적은 도시 간 긴 구간에 여러 입력 묶음을 배치하는 고속 타임어택용. [DB ICE Sprinter](https://www.bahn.de/service/ueber-uns/zugtypen/ice-sprinter) |
| 독일–폴란드 / Berlin–Warszawa / EC | DB는 Berlin 및 Frankfurt (Oder)에서 Warszawa로 가는 EuroCity 직통 연결을 안내한다. | Berlin → Frankfurt (Oder) → Warszawa를 국가 간 확장 챕터로 사용한다. 중간 정차역을 추가할 때 해당 운행 변형을 다시 확인한다. 폴란드 문자 처리 규칙은 독일 문자 규칙과 별도로 준비한다. [DB 유럽 직통 연결의 Warszawa 항목](https://www.bahn.de/angebot/urlaub/staedtereisen/direktverbindung-europa) |

이 예시는 **확인일의 공식 자료에 기반한 게임 여정**이며 여행 계획용 최신 시간표가 아니다. VBB RE1 페이지는 2026년 6월 14일~12월 12일 공사에 따른 변경을 별도로 안내한다. DB의 2026 장거리 지도도 모든 정차·개별 운행을 표시하지 않고 공사 변동이 가능하다고 밝힌다. DB 지도의 도식 자체를 게임 배경으로 복사하는 대신, 확인한 사실을 자체 데이터에 기록한다. [DB 2026 지도 제공 페이지](https://www.bahn.de/service/ueber-uns/zugtypen/streckenkarte)

`RE1`만 전역 ID로 사용하면 안 된다. DB Regio Mecklenburg-Vorpommern에도 **Hamburg–Schwerin–Rostock RE1**이 있다. 운영 지역과 운영사가 다르므로 예를 들면 `de.berlin-brandenburg.odeg.re1.eastbound.2026`처럼 구분한다. [DB Regio Hanse-Express RE1](https://www.dbregio-mecklenburg-vorpommern.de/db-regio-mv/ausgewaehlte-strecken/hamburg-rostock-re1)

또한 **서비스 종류(ICE) / 노선 번호 / 개별 운행편 번호 / 차량 형식(예: ICE 3)은 서로 다른 값**으로 설계한다. DB는 비슷한 경로의 열차들을 노선으로 묶는다고 설명하며, 같은 노선에서도 정차·방향·운행일 변형이 존재한다. 이번 예시의 ICE Sprinter 구간에는 검증하지 않은 노선 번호나 개별 편명을 임의로 붙이지 않았다. [DB 장거리 노선 설명](https://www.bahn.de/service/ueber-uns/zugtypen/streckenkarte)

## 게임 규칙 제안: 여행과 타자 실력을 함께 살리기

아래는 구현 제안이며 실제 철도 운행 조건이나 이미 제공 중인 PVP 기능에 관한 설명이 아니다.

| 모드 | 구체적인 플레이 | 결과와 다음 단계 |
| --- | --- | --- |
| 캠페인 | RE 지역 구간을 8~14개 목적지로 나눈다. 역명을 완성할 때 다음 역으로 진행하고 주변 관광 카드가 등장한다. 장거리 ICE/EC는 실제 정차역을 바꾸지 않으면서 한 구간 안에 역명 복습·연결 구간 명칭 등 명시된 추가 입력 묶음을 둔다. | 현재 별·점수·실패 규칙을 유지하되 기기별 목표를 조정한다. ★ 완주와 최소 정확도, ★★ 목표 점수, ★★★ 더 높은 점수와 정확도처럼 조건을 화면에 명시한다. 수치는 플레이테스트 후 확정한다. |
| 고정 노선 타임어택 | 동일한 노선·방향·텍스트 버전의 전체 입력을 가장 빨리 완주한다. | 완주 시간 순으로 정렬하고 같은 시간은 정확도, 그다음 원문 보너스 점수로 비교한다. 점수 랭킹은 시간 랭킹과 별도로 둔다. |
| 90초 스프린트 | 같은 입력 순서로 90초 동안 진행한다. 입력을 미리 끝내면 같은 규칙으로 이어지는 다음 묶음을 사용한다. | 정확히 처리한 정규화 입력 단위 수로 순위를 정한다. 지도상 실제 이동 km는 순위에 사용하지 않는다. |
| 친구 고스트 대전 | 친구가 남긴 입력 진행 기록을 같은 지도에서 반투명 열차로 재생한다. | 비동기 경쟁부터 도입한다. 승패와 원문 보너스, 정확도, 기기 프로필을 함께 보여준다. |

ICE처럼 생긴 열차를 선택했다는 이유로 점수나 이동 성능을 높이지 않는다. 열차 외형은 수집 보상으로 두고, 타자 속도에 따라 화면상의 이동·가속을 연출한다. 실제 최고속도를 넣을 경우 차량 자료를 별도로 확인한 정보 카드에 표시하고 **게임의 속도 연출 수치와 구분**한다. 그래야 RE 구간의 긴 역명과 ICE의 긴 도시 간 거리가 불공정한 점수 차이를 만들지 않는다.

원문 보너스는 현재 의도대로 **켜고 끄는 설정 없이**, 올바른 `ä / ö / ü / ß` 입력에 자동 적용한다. 현재 엔진의 특수문자 1개당 기본 보너스는 20점이며 최종 점수는 정확도·속도 계산의 영향을 받는다. PVP에서도 같은 규칙을 공개한다. `ü`와 분해형 `u + ◌̈`처럼 동일한 문자는 같은 결과로 정규화하고 보너스를 한 번만 준다. `ß`와 대체 입력 `ss`의 키 입력 수가 다른 점을 고려해 경쟁 진행률은 원시 키다운 횟수로 계산하지 않는다.

## 모바일과 컴퓨터의 공정성

**초기 랭킹은 터치 입력과 물리 키보드 입력을 분리하는 것이 가장 명확하다.** 같은 별 등급이라도 각 프로필의 목표 속도·제한 시간을 사용한다. 현재 모바일 속도 계수는 출발점일 뿐이며, 실사용자 완주율·오타율·평균 입력 속도를 보고 조정해야 한다. ‘휴대폰은 무조건 절반 속도’ 같은 고정 가정을 영구적인 공정성 증명으로 쓰지 않는다.

친구끼리 다른 기기로 경쟁하는 것은 우선 친선전으로 제공한다. 선택 사항으로 연습 결과 대비 달성률을 비교할 수 있지만, 일부러 연습 점수를 낮출 수 있어 공식 순위에 바로 사용하지 않는다. 별도의 사용자 토글 없이 앱 종류로 기본 프로필을 고르는 기존 방향을 유지할 수 있으나, 휴대폰의 외장 키보드·웹 자동 입력까지 완벽히 판별하는 것은 별개의 문제다.

고스트·경쟁 기록에는 다음 값을 남기는 구조를 제안한다.

- 노선 ID·방향·정차 변형·텍스트 버전 또는 해시와 규칙 버전.
- 입력 프로필, 시작 시각, 정규화된 진행 변화·오타·원문 보너스의 상대 시각 기록.
- 게임이 계산한 결과와 검증 상태. 다른 앱에서 입력한 문장 등 불필요한 키보드 기록은 수집하지 않는다.

친선용 로컬 고스트와 검증된 온라인 순위를 구분한다. 온라인 순위는 서버에서 같은 규칙으로 이벤트를 재생해 시간·진행량·점수를 다시 검증하고, 클라이언트가 보낸 최종 점수만 신뢰하지 않는다. 실시간 PVP는 그 이후에 공통 시작 시각·권위 있는 결과 계산·연결 종료 규칙을 추가한다. 솔로의 일시정지는 유지하되, 순위전은 포커스 이탈·일시정지 처리 규칙을 시작 전에 고정한다. 여기서는 실시간 PVP를 구현하지 않았다.

## 권장 개발 순서

1. 실제 서비스 데이터에 운영사·지역·방향·변형·확인일을 추가하고 위 3개 예시 중 하나를 짧은 캠페인으로 검증한다.
2. 자체 열차 아트와 실제 지리 지도를 연결한다. 현재 도식 연결선을 쓰는 동안에는 정확한 철도 선형이라는 표현을 피한다.
3. 같은 콘텐츠를 재현할 수 있는 타임어택·로컬 고스트를 만들고 모바일/키보드 기준을 각각 보정한다.
4. 서버 검증이 있는 친구 기록 공유·분리된 랭킹을 붙인다.
5. 실제 차량 재현이 제품에 필요해지면 구체적인 모델·도색·사용 화면을 기준으로 권리 확인 및 라이선스 협의를 진행한다. 그 결과를 차량 에셋 메타데이터에 반영한 뒤 배포한다.

이 문서는 한국·기타 배포 국가의 모든 법률, 개별 상표·디자인 등록의 현재 효력, 특정 3D 판매 자산의 계약을 조사한 것은 아니다. 확인한 공식 이용 조건과 검증한 노선 사실을 바탕으로 다음 제작 결정을 돕는 범위로 사용한다.
